31/07/2026: How Naturalmotion endorphin assets are encrypted

endorphin has been a niche interest of mine for a good part of my life, naturalmotion's ragdoll tech has always impressed little old me, now that im older and wiser i can delve into how endorphin's assets are encrypted.
endorphin has 2 editions: professional and learning. professional edition only compresses the files with zlib, while learning edition applies a extra layer of aes encryption into the assets. almost all naturalmotion assets are just .xml files under the hood. we'll start with the professional edition.

a typical asset from endorphin PE is structured as follows:

-zlib data
-integer that represents original data size (4 bytes)
-endorphin signature (16 bytes)

and a typical asset from endorphin LE is structured as follows:

-AES-encrypted data(zlib data, 4 byte integer)
-endorphin signature (16 bytes)


decompiling a PE asset is fairly easy. all it takes is a single line of python: "zlib.decompress(rawfile[:-20])".
how about the LE asset? how is the key for the AES encryption generated? its actually rather simple as well, take in the following structure:
struct aeskeybuffer
{
std::string key1;
std::string key2;
std::string key3;
bool use_haspkey;
}
 the program constructs a variable of this structure and assigns the following values to it:
key1 = "8c22115edd7d4277881476f9b2b7fd55";
key2 = "09730b838dfc44ebb096309ef5125ef";
key3 = "7178b59a554f4e819c538e8046714fa";
use_haspkey = false;
 key1 is seemingly unused in code, key2 is always used, and key3 is only used if use_haspkey is false (it is never true so key3 is always used). afterwards, during the encryption/decryption process, endorphin performs a XOR operation for every character in the 2 previously selected keys, resulting in a key that can be used to encrypt and decrypt files. the simple python script below represents this process:

key1 = bytes("8c22115edd7d4277881476f9b2b7fd55\0", 'utf-8') #unused
key2 = bytes("09730b838dfc44ebb096309ef5125ef\0", 'utf-8')
key3 = bytes("7178b59a554f4e819c538e8046714fa\0", 'utf-8')
key = bytes(i ^ j for i, j in zip(key2, key3))
cipher = AES.new(key, AES.MODE_CBC, b"\x00" * 16)
decrypted = cipher.decrypt(zlib.decompress( rawfile[:-4] )[:-16])
encrypted = cipher.encrypt(zlib.compress( decrypted + bytes(len(decrypted)) )) + endorphinLE_signature
the null terminator, oddly enough, is included in the key generation process, since std::string automagically adds one when it is assigned a string with no null terminator.
with the python script above, you can already decompile & compile all endorphin LE and PE assets ! have fun with it :)
